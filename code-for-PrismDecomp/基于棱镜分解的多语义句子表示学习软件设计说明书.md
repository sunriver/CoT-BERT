## 1. 引言

### 1.1 编写背景和目的

#### 1.1.1 编写背景

随着互联网技术的飞速发展与数字化浪潮的全球普及，海量的文本数据已渗透到社会生活的每一个角落。在这些纷繁复杂的文本信息中，如何精准、高效地捕捉并提取出蕴含在自然语言背后的深层语义信息，已成为自然语言处理（Natural Language Processing, NLP）领域最为核心的挑战之一。句子表示学习（Sentence Representation Learning）作为连接原始文本与下游业务逻辑的桥梁，旨在将变长的文本序列映射为定长的低维稠密向量（即嵌入，Embedding）。这种表示方式不仅极大地方便了机器进行数学计算，更在信息检索、语义问答、文本聚类、情感分析以及机器翻译等关键任务中发挥着不可替代的基础性作用。

回顾发展历程，句子表示学习经历了从“浅层统计”到“深度表征”的深刻演变。早期的方法如词袋模型（Bag-of-Words, BoW）和TF-IDF主要依赖词频统计，完全忽略了词序信息。随后，Word2Vec和GloVe等静态词向量技术的出现，开启了分布式表示的新纪元，但它们由于无法处理“一词多义”现象，在复杂语境下的表现依然受限。直到以BERT（Bidirectional Encoder Representations from Transformers）为代表的预训练语言模型（Pre-trained Language Models, PLMs）横空出世，通过在大规模无监督语料上进行掩码预测任务，模型才真正获得了捕获动态上下文语义的能力。

然而，尽管预训练模型在诸多有监督任务上取得了令人瞩目的成就，但在无监督句子表示学习领域，直接使用预训练模型导出的表示往往面临严重的“各向异性”（Anisotropy）问题。研究发现，BERT生成的句子向量在空间中并非均匀分布，而是呈现出一种狭窄的“锥形”结构，这导致即便是完全无关的句子，其余弦相似度也可能极高，极大限制了模型在语义相似度计算（STS）任务中的分辨力。

针对这一瓶颈，学术界近年来涌现出了以SimCSE、PromptBERT等为代表的对比学习方法。这些方法通过对同一句子施加不同的随机扰动（如Dropout掩码或提示模板变换），构建正负样本对，强制模型在向量空间中拉近相似句子的距离并推远无关句子的距离。虽然这种“单向量表征+对比学习”的框架在性能上取得了突破，但在更深层次的语义捕获上，仍然存在三大核心短板：

首先是“语义维度单一”问题。人类语言具有极高的丰富度和多面性，一个简单的句子往往包含了情感倾向、主题范畴、语法结构、逻辑关系以及时空背景等多个维度的信息。现有的方法通常尝试将这些复杂的信息强行压缩进一个单一的高维向量中。这种“一刀切”的压缩方式往往导致不同维度的语义信息相互缠绕、混淆，形成了一种“语义塌陷”现象，难以满足不同下游任务对特定细粒度特征的需求。

其次是“弱信号丢失”问题。在神经网络的前向传播和特征压缩过程中，占据主导地位的显性语义（如高频词汇对应的主题信息）往往会遮蔽那些细微但关键的隐性语义（如特定的语气词或罕见的实体属性）。由于缺乏显性的分离与增强机制，这些弱信号极易在多层非线性变换中被当作噪声过滤掉，从而导致生成的表示缺乏细腻度。

最后是“表示能力的泛化局限”。单一向量在面对多样化的业务场景时，其表达能力往往捉襟见肘。例如，在情感分类任务中，模型可能需要更关注形容词的特征；而在法律文档检索中，模型则需要更关注实体与逻辑连接词。如果无法显式地将这些语义维度拆解开来，模型就无法在不同任务中灵活地调用相应的特征。

正是在这样的技术背景与现实需求下，本软件提出了基于“棱镜分解”的创新性解决方案。受光学现象启发，我们发现复杂的句子语义与混合的白光具有惊人的相似性——它们都是多种纯粹成分的复合体。通过设计一种模拟棱镜作用的“语义分解器”，本软件致力于将缠绕在一起的混合向量投影到多个相互独立（正交）的子空间中，从而像分解七色光一样，显式地提取出句子的多维度子语义。这种设计思路不仅是对现有对比学习范式的有力补充，更是在表征哲学上的重大尝试。通过引入局部信号增强与残差融合机制，我们不仅能够防止弱信号的丢失，更能通过“分而治之”的策略提升向量空间的解析度。本软件的研发，旨在为自然语言处理提供一种更高精度、更具可解释性且更具泛化能力的表示学习工具，为处理海量复杂文本提供更加坚实的技术底座。

5. **模型评估**：集成SentEval评估框架，支持多种语义文本相似度（STS）任务评估

1. **光学类比创新**：将物理现象与NLP任务结合，类比新颖，将句子表示类比为白光，分解器类比为棱镜
2. **多语义分解**：将单一句子表示分解为多个语义维度，每个维度专注于特定的语义信息
3. **局部信号增强**：针对性地强化弱信号，防止信号弱的语义被忽略
4. **残差融合机制**：直接放大子语义信号，同时保留原始信息
5. **简化训练目标**：移除子语义层级的InfoNCE损失，避免训练目标冲突，提高泛化性能
6. **跨平台支持**：支持Mac M4（MPS）和Linux CUDA平台

## 2. 软件整体框架结构

### 2.1 设计哲学与原理

本软件的核心设计灵感源于光学中的“棱镜分解”现象。正如白光通过棱镜可以被分解为七种不同频率的单色光，复杂的句子语义也可以被视为多种单一语义维度的叠加。

软件将传统的单向量句子表示类比为“混合白光”，通过设计的“语义分解器”（类比棱镜）将其投射到多个正交或近正交的子空间中，从而显式地分离出情感、主题、语法、时空等不同维度的语义信号。这种设计哲学旨在突破单向量表示的局限性，通过“分而治之”的策略提高语义表达的细腻度。

### 2.2 整体架构设计

软件采用严谨的层次化架构设计，从底向上分为五个核心层次：

1.  **输入层**：负责原始文本的读取与Tokenization预处理，支持大规模语料的流式加载。
2.  **编码层（编码器）**：以预训练的BERT模型为底座，利用Masked Language Modeling（MLM）机制提取句子的深层特征表示。
3.  **分解增强层（核心逻辑）**：这是软件的算法核心，包含语义分解、软正交约束和局部信号增强三个步骤。
4.  **融合层（残差连接）**：利用残差学习的思想，将分解增强后的细粒度语义与原始粗粒度语义进行非线性融合。
5.  **输出与任务层**：在训练阶段生成对比学习损失，在评估阶段输出高维语义向量。

### 2.3 核心模块功能

软件由以下几个相互协作的核心模块组成：

*   **多语义分解模块**：通过可学习的分解矩阵，将 $D$ 维的句子向量映射到 $K \times D$ 维空间，通过视图变换还原为 $K$ 个子语义向量。
*   **正交约束模块**：引入软正交损失函数（Soft Orthogonal Loss），在训练过程中强制要求不同语义维度之间的余弦相似度接近于零，确保语义不冗余。
*   **信号增强模块**：针对每个子语义维度，使用独立的轻量级感知机进行特征放大，补偿在分解过程中可能产生的能量损耗。
*   **残差融合模块**：通过自适应权重，将所有增强后的子信号与原始信号相加，实现语义信息的“全反射”回传。

### 2.4 数据处理流程

软件的数据处理遵循“编码-分解-增强-融合”的闭环链路：

1.  **数据流向 A（训练）**：输入句子经过两次 Dropout 产生两个视图，分别执行分解融合操作，最后计算两者的 InfoNCE 相似度。
2.  **数据流向 B（评估）**：输入句子经过单次前向传播，通过棱镜分解模块提取融合后的向量，直接输出用于相似度计算。

## 3. 模块设计介绍

### 3.1 语义分解模块

#### 3.1.1 模块对应代码

**文件位置**：`prism_decomp_model.py`

**主要类**：`SemanticDecomposer`

**核心代码片段**：

```python
class SemanticDecomposer(nn.Module):
    """
    语义分解器：将句子表示分解为多个语义维度
    参考光学中白光通过棱镜分解为七色光的原理
    """
    def __init__(self, hidden_dim: int, num_semantics: int = 7):
        super().__init__()
        self.hidden_dim = hidden_dim
        self.num_semantics = num_semantics
        
        # 可学习的分解矩阵
        self.decomposition_matrix = nn.Parameter(
            torch.randn(hidden_dim, num_semantics * hidden_dim) * 0.1
        )
        
        # 正交约束确保语义独立性
        self.orthogonal_constraint = OrthogonalConstraint()
        
        # 激活函数
        self.activation = nn.GELU()
        
    def forward(self, sentence_repr, compute_orth_loss=True):
        # 应用分解矩阵
        decomposed = torch.matmul(sentence_repr, self.decomposition_matrix)
        
        # 重塑为多个语义表示
        semantic_reprs = decomposed.view(-1, self.num_semantics, self.hidden_dim)
        
        # 应用激活函数
        semantic_reprs = self.activation(semantic_reprs)
        
        # 应用软正交约束，获取软正交损失
        semantic_reprs, orth_loss = self.orthogonal_constraint(semantic_reprs, compute_loss=compute_orth_loss)
        
        return semantic_reprs, orth_loss
```

#### 3.1.2 功能描述

语义分解模块借鉴光学色散原理，利用可学习矩阵将BERT编码的768维向量投影至高维空间，并重塑为多个独立的子语义向量。通过软正交约束确保不同维度语义独立且互不冗余，为后续精细化特征增强奠定基础。

#### 3.1.3 主要业务算法 and 流程图

**核心算法**：

1. **线性投影**：`decomposed = H * W`，其中W是大小为`(D, K*D)`的权重矩阵。
2. **重塑操作**：将1D向量重塑为K个D维子向量。
3. **软正交惩罚**：计算 `||H^T H - I||_F^2` 作为损失。

1. **输入投影**：接收 BERT 提取的 768 维句子向量 $H$。
2. **线性扩张**：利用分解矩阵将其投影至高维空间。
3. **维度切割**：通过 Reshape 操作将其“折叠”为 7 个独立的语义子向量。
4. **正交约束检查**：在输出前计算子向量间的相似度矩阵，生成正则化损失。

### 3.2 信号增强模块

#### 3.2.1 模块对应代码

**文件位置**：`prism_decomp_model.py`

**主要类**：`SignalEnhancer`

#### 3.2.2 功能描述

信号增强模块针对分解后可能变弱的语义信号进行定向补偿。通过标量权重调整振幅，并结合轻量级MLP残差网络放大隐性特征。该机制确保了细微语义（如语气转折）不被忽略，显著提升了模型对复杂语境的捕捉精度。

#### 3.2.3 主要业务算法 and 流程图

**核心算法**：

- `h_i_enhanced = h_i * α + MLP(h_i)`

**流程图**：

![信号增强模块流程图](/Users/lmf/Documents/local/code/论文项目代码/软著/菱镜分解/images/05_enhancer_flow.png)

**图 3-2 信号增强流程说明**：
1. **权重缩放**：引入可学习参数 $\alpha$ 对子语义向量进行基础振幅调整。
2. **深度特征提取**：将向量送入由两层线性层和 GELU 激活构成的轻量级 MLP。
3. **残差跳连**：将 MLP 提取的增强特征与原始子语义相加，完成局部信号补偿。

### 3.3 残差融合模块

#### 3.3.1 模块对应代码

**文件位置**：`prism_decomp_model.py`

**主要类**：`ResidualFusion`

#### 3.3.2 功能描述

残差融合模块模拟光学全反射原理，将增强后的多维子信号进行加权聚合。通过全局残差连接，将细节增量注入原始BERT表征中。这种方式在保留通用语义稳定性的同时，显著增强了最终向量对微观语义变化的敏感度。

#### 3.3.3 主要业务算法 and 流程图

**核心算法**：

- `h_final = h_original + sum(h_i_enhanced)`

**流程图**：

![残差融合模块流程图](/Users/lmf/Documents/local/code/论文项目代码/软著/菱镜分解/images/06_fusion_flow.png)

**图 3-3 残差融合流程说明**：
1. **语义汇总**：通过 `sum` 算子将增强后的 7 个子语义维度重新聚合成一个综合特征。
2. **全局残差加和**：将综合特征与最初进入模块的原始向量进行相加，类似光学的“全反射”原理，确保最终输出包含全量语义。

### 3.4 多语义分解增强模块

#### 3.4.1 模块对应代码

**文件位置**：`prism_decomp_model.py`

**主要类**：`MultiSemanticSPR`

#### 3.4.2 功能描述

多语义分解增强模块作为编排中枢，管理“分解-增强-融合”全流水线。它负责各子模块间的参数共享与梯度回传调度，并动态计算软正交损失。通过容器化设计，它实现了多维度语义处理逻辑的闭环组织与高效执行。

#### 3.4.3 主要业务算法 and 流程图

**流程图**：

![多语义分解增强模块流程图](/Users/lmf/Documents/local/code/论文项目代码/软著/菱镜分解/images/07_multispr_flow.png)

**图 3-4 多语义分解增强模块编排说明**：
该模块作为流水线控制器，定义了逻辑流转顺序：
1. 调用 `Decomposer` 获得原始子语义流。
2. 触发 `SignalEnhancer` 阵列对每个子语义分支进行并行增强。

### 3.5 训练评估模块

1. **无监督InfoNCE损失**：使用Dropout作为数据增强，构建正负样本对。

## 4. 接口设计

### 4.1 模型接口

#### 4.1.1 模型初始化接口

**接口定义**：

```python
model = BertForPrismDecomp.from_pretrained(
    model_name_or_path: str,
    config: Optional[PretrainedConfig] = None,
    model_args: Optional[ModelArguments] = None,
    **kwargs
)
```

**接口说明**：
该接口用于创建并初始化 `BertForPrismDecomp` 模型实例。它继承自 Hugging Face 的 `BertPreTrainedModel`，支持从本地路径或 Hugging Face Hub 加载预训练权重。在初始化过程中，模型会根据 `model_args` 中的 `num_semantics` 参数自动构建多语义分解模块和残差融合模块。同时，它会自动抑制由于自定义模块（如 `multisemantic_spr`）未在预训练权重中找到而产生的初始化警告。

**参数说明**：

- `model_name_or_path`：预训练模型路径或 Hugging Face 模型标识符。
- `config`：模型配置对象（可选），用于指定 BERT 的超参数。
- `model_args`：模型参数对象，必须包含 `num_semantics`（语义维度数量）、`temperature`（对比学习温度）和 `lambda2`（正交损失权重）等核心参数。
- `**kwargs`：传递给底层 BERT 模型的其他可选参数。

**返回值**：

- `model`：已加载预训练权重并完成棱镜分解组件初始化的 `BertForPrismDecomp` 模型实例。

#### 4.1.2 前向传播接口

**接口定义**：

```python
outputs = model(
    input_ids: torch.Tensor,
    attention_mask: Optional[torch.Tensor] = None,
    sent_emb: bool = False,
    **kwargs
)
```

**接口说明**：
前向传播接口是模型处理数据的核心入口，通过 `sent_emb` 参数区分训练和推理模式：

- **训练模式 (`sent_emb=False`)**：
  模型执行完整的棱镜分解流程。首先通过 BERT 编码器获取原始句子表示，然后由 `MultiSemanticSPR` 模块将其分解为多个子语义并执行信号增强。接着，`ResidualFusion` 模块将增强后的子语义与原始表示融合。最后，模型计算全局 InfoNCE 损失和子语义间的软正交损失，返回包含总损失和 logits 的 `SequenceClassifierOutput` 对象。

- **推理模式 (`sent_emb=True`)**：
  该模式专为评估和特征提取设计。模型仅执行必要的编码和分解融合操作，不计算损失。输出经过 L2 归一化后的融合句子向量，适用于计算余弦相似度。该模式在内部调用 `sentemb_forward` 方法，以确保在评估大规模数据集（如 SentEval）时的执行效率。

**参数说明**：

- `input_ids`：输入 token ID，形状为 `(batch_size, seq_len)`。
- `attention_mask`：注意力掩码，用于忽略填充位（padding tokens）。
- `sent_emb`：模式切换开关。`False` 表示训练模式（计算损失），`True` 表示推理模式（返回归一化特征向量）。

**返回值**：

- 训练模式：`SequenceClassifierOutput`，包含 `loss`（总损失）和 `logits`（融合后的特征向量）。
- 推理模式：`BaseModelOutputWithPoolingAndCrossAttentions`，其 `pooler_output` 为归一化后的多语义增强句子表示。

### 4.2 训练接口

#### 4.2.1 训练器初始化接口

**接口定义**：

```python
trainer = PrismDecompTrainer(
    model: PreTrainedModel,
    args: TrainingArguments,
    train_dataset: Optional[Dataset] = None,
    eval_dataset: Optional[Dataset] = None,
    tokenizer: Optional[PreTrainedTokenizerBase] = None,
    model_args: Optional[ModelArguments] = None,
    **kwargs
)
```

**接口说明**：
该接口用于初始化 `PrismDecompTrainer`，它是针对本软件特有的棱镜分解逻辑定制的训练管理类。该训练器集成了 SentEval 自动化评估框架，能够在训练过程中实时监控模型在 STS 语义相似度任务上的表现。它负责管理完整的训练生命周期，包括优化器状态维护、学习率调度、分布式训练同步以及基于最佳指标的模型自动保存。

**参数说明**：

- `model`：已初始化的 `BertForPrismDecomp` 模型实例。
- `args`：Hugging Face 标准训练参数对象，定义批次大小、学习率、保存策略等。
- `train_dataset`：用于无监督对比学习的训练数据集。
- `eval_dataset`：验证数据集，通常用于计算验证集损失。
- `tokenizer`：配套的分词器实例。
- `model_args`：包含模型特有超参数（如 `lambda2`）的对象，用于在评估时传递给模型。

**返回值**：

- `trainer`：功能完备的 `PrismDecompTrainer` 训练器实例。

#### 4.2.2 训练方法接口

**接口定义**：

```python
train_output = trainer.train(
    model_path: Optional[str] = None,
    trial: Optional[Union["optuna.Trial", Dict[str, Any]]] = None
)
```

**接口说明**：
该接口启动模型的训练流程。它执行无监督对比学习的迭代计算，自动处理多 GPU/MPS 的并行加速。在每个 epoch 或设定的步数结束时，它会触发评估逻辑，并根据 `metric_for_best_model` 配置自动锁定并保存性能最强的模型权重。

**参数说明**：

- `model_path`：可选。指向之前保存的检查点路径，用于断点续训。
- `trial`：可选。用于 Optuna 等超参数搜索框架的试验对象。

**返回值**：

- `train_output`：包含总训练时长、平均损失和全局步数等信息的输出对象。

#### 4.2.3 评估方法接口

**接口定义**：

```python
metrics = trainer.evaluate(
    eval_dataset: Optional[Dataset] = None,
    ignore_keys: Optional[List[str]] = None,
    metric_key_prefix: str = "eval",
    eval_senteval_transfer: bool = False
) -> Dict[str, float]
```

**接口说明**：
该接口执行针对语义句子表示的专项评估。不同于传统的分类评估，该接口会调用 SentEval 库，在 STS12-STS16 等标准测试集上计算模型生成的句子向量之间的余弦相似度，并得出斯皮尔曼相关系数。它能够全面衡量模型对多维度语义的捕获能力。

**参数说明**：

- `eval_dataset`：可选。用于基础验证的数据集。
- `eval_senteval_transfer`：布尔值。若为 `True`，则会额外执行下游迁移任务（如文本分类）的评估。

**返回值**：

- `metrics`：包含 `eval_stsb_spearman`、`eval_avg_sts` 等核心性能指标的字典。

### 4.3 评估脚本接口

#### 4.3.1 命令行接口

```bash
python prism_decomp_evaluation.py <config_file>
```

**接口说明**：

**参数说明**：

#### 4.3.2 配置文件接口

```yaml
model_name_or_path: "/path/to/trained_model"

```

**接口说明**：
